Selectors

Before you style anything you have to say which elements you mean.

Type a selector, see what it hits

The six you need first

p          { }  /* element: every paragraph */
.done      { }  /* class: anything with class="done" */
#now       { }  /* id: the one element with id="now" */
li.done    { }  /* both: an li that is also .done */
ul > li    { }  /* child: li directly inside ul */
li:hover   { }  /* state: while the pointer is over it */

Specificity, the short version

When two rules disagree, the more specific selector wins: an id beats a class, a class beats an element. If they tie, the later rule wins. That is the "cascade" in Cascading Style Sheets.

Common mistake. Reaching for !important. Fix the selector instead; !important only makes the next conflict harder to solve.
